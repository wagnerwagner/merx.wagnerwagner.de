## Create checkout page

Merx comes with a [checkout blueprint](/reference/blueprints/pages/checkout). Create a new page in the Panel and select *Checkout* as template. By default the status of the page is *unlisted*.

## Create checkout form

Add form fields for the data you need to collect from your customer. In this example we just collect the email address. This would be the place to add fields for name and shipping address.
As the payment gateway we’ll use *invoice* for the moment. It takes no payment, so Merx only offers it once you switch it on:

```php title="/site/config/config.php"
<?php

return [
  'wagnerwagner.merx.gateways' => [
    'invoice' => true,
  ],
];
```

```php title="/site/templates/checkout.php"
…
<form id="checkout-form" action="<?= url('api/shop/checkout') ?>" method="post">
  <label>
    Email
    <input type="email" name="email" autocomplete="email" required>
  </label>
  <input type="hidden" name="payment_gateway" value="invoice">
  <button>Submit order</button>
</form>
…
```

As long as all data is valid, the customer is redirected directly to the order page, where they see the summary of their order.

When there are validation errors (e.g. no email provided) the API endpoint ([`/api/shop/checkout `](/reference/api/routes/shop-checkout-post)) returns a JSON with details of the validation error. Continue with **[Validate checkout](/guide/getting-started/validate-checkout)** to learn how to define required fields and how to use JavaScript to handle the JSON data.

## Show why an order failed

When an order can’t be completed, e.g. because the customer canceled the payment, Merx sends them back to the checkout page. [`merx()->error()`](/reference/classes/merx/error) returns what went wrong, once: an array with the translation `key` and the `message`, or `null`.

```php title="/site/templates/checkout.php"
<?php if ($error = merx()->error()): ?>
  <p role="alert"><?= esc($error['message']) ?></p>
<?php endif ?>
```
