Title: Taxes

----

Headline: 

----

Intro: Each product names a tax rule, and each tax rule sets a rate: a number like `0.19`, or a PHP function that returns one.

----

Text:

The tax rule sets are defined in the [`taxRules`](/reference/options/config-options/tax-rules) option. Each tax rule is defined by a key and an array with following items.

## Options per tax rule

| Name | Type | Default | Description |
| -- | -- | -- | -- |
| `name` | `string|function` | Key of the rule | |
| `rate` | `float|function` | `null` | Tax rate as a decimal, e.g. `0.19` for 19 %, or a function returning one. The function gets the [`$kirby`](https://getkirby.com/docs/reference/objects/cms/app) object as its argument. |

## Set up default tax rate

If you only sell products of the same kind, a `default` rule with a fixed rate is all you need.

```php title="/site/config/config.php"
<?php

return [
	'wagnerwagner.merx.taxRules' => [
		'default' => [
			'rate' => 0.19,
		],
	],
];
```

## Set tax rate for each product

A product names its tax rule in the `taxRule` field. Without one, it uses the `default` rule.

```kirby title="/content/products/1_bike/product.en.txt"
Title: Bike

\----

Taxrule: reduced
```

The `taxRule` field of the [product blueprint](/reference/blueprints/pages/product) lists the rules from your config, and stays hidden while there is only one. In a product blueprint of your own, add the field with `type: taxrules`.


## Different tax rates for different countries

When the rate depends on something, pass a function instead of a number. It gets the [`$kirby`](https://getkirby.com/docs/reference/objects/cms/app) object, so you can for example use [`$kirby->languageCode()`](https://getkirby.com/docs/reference/objects/cms/app/language-code) to return a rate for each language.

```php title="/site/config/config.php"
<?php

return [
	'wagnerwagner.merx.taxRules' => [
		'default' => [
			'name' => fn (): string => t('taxRule.default', 'Standard rate'),
			'rate' => fn (?\Kirby\Cms\App $kirby): float => $kirby->languageCode() === 'de' ? 0.19 : 0.20,
		],
		'reduced' => [
			'name' => fn (): string => t('taxRule.reduced', 'Reduced rate'),
			'rate' => fn (?\Kirby\Cms\App $kirby): float => $kirby->languageCode() === 'de' ? 0.07 : 0.055,
		],
	],
];
```

Returning the correct tax rate for different countries could get very complicated. Stripe uses [*product tax codes*](https://docs.stripe.com/tax/tax-codes) (PTCs). In theory you could build something like that with Merx.

## Displaying the tax

The tax rate is applied to the price of the product. You can use [`$page->tax()`](/reference/classes/product-page/tax) to retrieve the tax rate and currency value.

```php title="/site/templates/product.php"
<?= $page->tax() ?> (<?= $page->tax()->rate() ?>)
<!-- €9.42 (19%) -->
```

## A cart with more than one tax rate

A cart that mixes rates — books at 7 %, everything else at 19 % — has no single rate, and [`$cart->total()`](/reference/classes/cart/total) says so: `tax->rate` is `null` and `tax->price` is the sum of the individual tax amounts.

```php title="A cart with one book at 7 % and one pair of shoes at 19 %"
$cart->total();            // €129.70
$cart->total()->tax;       // €19.70
$cart->total()->tax->rate; // null, because the items do not share a rate
```

So anything that prints the rate of a total has to cope with `null`. Use [`$cart->taxRates()`](/reference/classes/cart/tax-rates) for the breakdown instead. It returns one [`Tax`](/reference/classes/tax) per rate, lowest first, each carrying the total tax at that rate — which is what an invoice has to show anyway.

```php title="/site/snippets/cart.php"
<?php foreach ($cart->taxRates() as $tax): ?>
  <tr>
    <th colspan="3">incl. <?= $tax->rate() ?> VAT</th>
    <td><?= $tax ?></td>
  </tr>
<?php endforeach ?>
<!-- incl. 7% VAT   €0.70 -->
<!-- incl. 19% VAT  €19.00 -->
```

With a single rate the loop runs once, so the same snippet works for both kinds of shop.
