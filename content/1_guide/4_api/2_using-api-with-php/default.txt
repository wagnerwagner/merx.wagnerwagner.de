Title: Using API with PHP

----

Headline: 

----

Intro: Every cart and checkout operation is available in PHP, for shops that render the cart server-side.

----

Text:

The [API](/guide/api/concept) exists so your pages can stay cacheable. When that does not matter — a small catalog, no page cache, or a shop that has to work without JavaScript — you can do the same things in a template, a controller or a [route](https://getkirby.com/docs/guide/routing).

Both work on the same cart. `$site->cart()` and the API read from and write to the same session, so we can mix them freely.

| API route | PHP |
| ---- | ---- |
| `GET shop/cart` | [`$site->cart()`](/reference/options/site-methods/cart) |
| `POST shop/cart` | [`$cart->add()`](/reference/classes/cart/add) |
| `PATCH shop/cart` | [`$cart->updateItem()`](/reference/classes/cart/update-item) |
| `DELETE shop/cart` | [`$cart->remove()`](/reference/classes/cart/remove) |
| `POST shop/checkout` | [`$merx->initializeOrder()`](/reference/classes/merx/initialize-order) |
| `GET shop/success` | [`$merx->createOrder()`](/reference/classes/merx/create-order) |

## Showing the cart

[`$site->cart()`](/reference/options/site-methods/cart) returns the visitor’s [`Cart`](/reference/classes/cart). It is a collection of [`ListItem`](/reference/classes/list-item) objects, like the cart of an order, so the cart snippet from [Displaying order](/guide/getting-started/displaying-order#cart-snippet) shows it as well.

```php title="/site/templates/cart.php"
<?php snippet('cart', ['cart' => $site->cart()]) ?>
```

Because this makes the page different for every visitor, the page that includes it can no longer be cached.

## Changing the cart

Merx has no route that adds an item and sends the customer back to where they came from — the API answers with JSON, which is what a JavaScript client wants, but not what a browser should be shown. Let’s add a route of our own for that.

```php title="/site/config/config.php"
<?php

return [
  'routes' => [
    [
      'pattern' => 'cart/add',
      'method' => 'POST',
      'action' => function () {
        $request = kirby()->request();

        if (csrf((string)$request->get('csrf')) !== true) {
          go('/', 303);
        }

        try {
          cart()->add([
            'page' => (string)$request->get('page'),
            'quantity' => (float)$request->get('quantity', 1),
          ]);
        } catch (\Kirby\Exception\Exception $exception) {
          // Show the message on the next page, e.g. via the session
          kirby()->session()->set('cartError', $exception->getMessage());
        }

        // A page of this site, never a URL the form could point anywhere
        go(page((string)$request->get('redirect'))?->url() ?? '/', 303);
      },
    ],
  ],
];
```

The form posts to that route instead of the API endpoint and tells it where to go afterwards.

```php title="/site/templates/product.php"
<?php /** @var \Wagnerwagner\Merx\ProductPage $page */ ?>

<span class="price"><?= $page->price() ?></span>

<form action="<?= url('cart/add') ?>" method="post">
  <input type="hidden" name="csrf" value="<?= csrf() ?>">
  <input type="hidden" name="page" value="<?= $page->uuid() ?>">
  <input type="hidden" name="redirect" value="<?= $page->uuid() ?>">
  <input type="number" name="quantity" min="1" value="1">
  <button>Add to cart</button>
</form>
```

[`$cart->remove()`](/reference/classes/cart/remove) and [`$cart->updateItem()`](/reference/classes/cart/update-item) work the same way. Both take the item’s `key`, which is the page’s UUID unless you set one yourself.

```php title="/site/config/config.php"
cart()->remove($request->get('key'));

cart()->updateItem($request->get('key'), [
  'quantity' => (float)$request->get('quantity'),
]);
```

> [!CAUTION]
> Never trust what the form sends. The API filters the request body before it reaches the cart, and your own route has to do the same. Cast `quantity` to a number, and do not pass the whole request body through — a `price` in it would replace the product’s own.

## Checkout

The checkout needs no route of your own. [`/api/shop/checkout`](/reference/api/routes/shop-checkout-post) answers a browser with a redirect and a JavaScript client with JSON, so the plain form from [Create checkout](/guide/getting-started/create-checkout) already works without JavaScript.

The same is true for the way back: `api/shop/success` completes the payment, empties the cart and redirects to the order page on its own.
