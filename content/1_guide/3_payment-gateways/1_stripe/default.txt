Headline: 

----

Intro: With Stripe you can offer multiple payment options like *credit card*, *PayPal*, *iDEAL*, *SEPA debit* and many more to your customers.

----

Text:

Your checkout shows Stripe’s [Payment Element](https://docs.stripe.com/payments/payment-element), an interface component (iFrame) with several payment options. The payment methods shown to your customer are determined by Stripe based on the currency, the customer’s location and the payment methods you have activated for your Stripe account.

To see which payment methods will be shown to your customers, you can use [Stripe’s Payment Review](https://dashboard.stripe.com/settings/payment_methods/review).

You can also show only [selected payment methods](#optional-show-only-specific-payment-methods), or a plain card field next to payment methods of your own, see [Stripe Card Element recipe](/cookbook/stripe-card-element).

For detailed information on the Payment Element, please read the **[Stripe Documentation *Accept a payment*](https://docs.stripe.com/payments/accept-a-payment?payment-ui=elements&api-integration=paymentintents)**.

## Collect payment details

Learn how to create the Payment Element, which is used to collect payment information.

### Set up Stripe.js

Add a hidden field called `payment_gateway` with the value `stripe` to the checkout form. This is used by Merx to complete the order.

Add the publishable key as a data attribute to the form element. The publishable key is required to initialize Stripe.js.

```php title="/site/templates/checkout.php"
<?php
$stripePublishableKey = option('wagnerwagner.merx.production') === true ? option('wagnerwagner.merx.stripe.live.publishable_key') : option('wagnerwagner.merx.stripe.test.publishable_key');
?>
<form id="checkout-form" action="<?= url('api/shop/checkout') ?>" method="post" data-stripe-publishable-key="<?= $stripePublishableKey ?>">
	<!-- Other form fields -->
	<input type="hidden" name="payment_gateway" value="stripe">
	<button>Submit order</button>
</form>
```

Add the `stripe.js` to the head of your HTML file. E.g. in a `head` snippet.

Stripe recommends including Stripe.js on every page of your site to leverage “Stripe’s advanced fraud functionality”. To accept payments, though, the checkout page is enough.

To learn more, see [Including Stripe.js | Stripe JS Reference](https://docs.stripe.com/js/including).

```php title="/site/snippets/head.php"
<?php if ($page->intendedTemplate()->name() === 'checkout'): ?>
  <script src="https://js.stripe.com/endive/stripe.js"></script>
<?php endif ?>
```

To initialize the [Stripe JavaScript API](https://docs.stripe.com/js) you need the publishable key from the checkout form.

```js title="/assets/js/checkout.js"
const checkoutForm = document.getElementById('checkout-form');
const stripePublishableKey = checkoutForm.dataset.stripePublishableKey;
const stripe = Stripe(stripePublishableKey);
```

### Add the Payment Element to your payment page

The Payment Element needs a place to live on your payment page. Create an empty DOM node (container) with a unique ID in your payment form:

```php title="/site/templates/checkout.php"
<form id="checkout-form" action="<?= url('api/shop/checkout') ?>" method="post" data-stripe-publishable-key="<?= $stripePublishableKey ?>">
	<!-- Other form fields -->
	<div id="payment-element">
		<!-- Elements will create form elements here -->
	</div>
	<button>Submit order</button>
</form>
```

### Retrieve the client secret

The Payment Element needs the client secret of a payment intent to know which payment methods fit the order. The [`/shop/stripe-client-secret`](/reference/api/routes/shop-stripe-client-secret-get) API endpoint creates the payment intent with the currency and the total of the cart, and returns its client secret. Merx remembers the payment intent in the visitor’s session, so there is nothing to add to the checkout form. Asked again, the endpoint updates that payment intent to the current total instead of creating another one, as long as nothing was paid with it.

```js title="/assets/js/checkout.js"
const response = await fetch('/api/shop/stripe-client-secret');
const { clientSecret } = await response.json();
```

### Create and mount the Stripe elements

```js title="/assets/js/checkout.js"
const elements = stripe.elements({
	clientSecret,
	locale: document.querySelector('html').lang,
});

// Create and mount the Payment Element
const paymentElement = elements.create('payment');
paymentElement.mount('#payment-element');
```

See [Elements Appearance API | Stripe Documentation](https://docs.stripe.com/elements/appearance-api) to learn how to change the look of the elements.

> [!CAUTION]
> The payment intent holds the cart total of the moment the client secret was fetched. If the cart changes afterwards, fetch the client secret again and create the elements again — reloading the checkout page does both. Merx refuses a payment that doesn’t match the cart with [`error.merx.amountMismatch`](/reference/options/translations/error-merx-amountmismatch) rather than shipping goods nobody paid for.

## Submit the payment to Stripe

As described in [Validate checkout](/guide/getting-started/validate-checkout) the personal data will be validated first against the personal data fields of the order blueprint. After that the payment data the customer entered into the elements is submitted to and validated by Stripe.

If you followed [Validate checkout](/guide/getting-started/validate-checkout), replace `window.location.href = json.redirectUrl;` with the following.

```js title="/assets/js/checkout.js"
  const { error } = await stripe.confirmPayment({
    // `Elements` instance that was used to create the Payment Element
    elements,
    confirmParams: {
      return_url: json.redirectUrl,
    },
  });

  if (error) {
    // This point will only be reached if there is an immediate error when
    // confirming the payment. Show error to your customer (for example, payment
    // details incomplete)
    checkoutForm.insertBefore(createErrorElement(error.message), event.submitter);
  }
```

After completing the payment the customer is redirected to the [order page](/guide/getting-started/displaying-order).

Most payment methods confirm the payment right away, so the `stripe` gateway sets the `datePaid` field of the [`OrderPage`](/reference/classes/order-page) to the current date in the background, and [`$orderPage->isPaid()`](/reference/classes/order-page/is-paid) returns `true`.

For some payment methods like *SEPA Direct Debit*, it can take up to 6 business days until the payment is confirmed. To ensure you don’t fulfill an order before payment clears, it’s recommended to use [webhooks](/guide/configuration/stripe-webhooks). You can set them up to automatically notify you, when payments are confirmed. They also complete the order of a customer who paid but never returned to your shop.

## Optional: show only specific payment methods

By default Stripe shows the payment methods you turned on in the [Stripe Dashboard](https://dashboard.stripe.com/settings/payment_methods). To offer only some of them, list them in `allowed_payment_method_types` of the [`stripe.paymentIntentParameters`](/reference/options/config-options/stripe-payment-intent-parameters) option. 

```php title="/site/config/config.php"
return [
  'wagnerwagner.merx.stripe.paymentIntentParameters' => [
    'allowed_payment_method_types' => ['card', 'ideal'],
    'capture_method' => 'automatic_async',
    'payment_method_options' => [
      'card' => ['capture_method' => 'manual'],
    ],
  ],
];
```

See Stripe’s API reference [Create a PaymentIntent](https://docs.stripe.com/api/payment_intents/create) to see all parameters. `amount` and `currency` are automatically added to by Merx.

Some payment methods [don’t allow manual capturing](https://docs.stripe.com/payments/capture-later) (e.g. *iDEAL*). If you want to use such payment methods, you need to set [`capture_method`](https://docs.stripe.com/api/payment_intents/create#create_payment_intent-capture_method) to `automatic_async`. The money is then taken before Merx checks that the payment covers the order. You can also set capture method for each payment [using the `payment_method_options`](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method#authorize-only).
