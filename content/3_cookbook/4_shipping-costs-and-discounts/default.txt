Title: Shipping costs and discounts

----

Headline: 

----

Intro: Shipping costs and discounts are list items with their own type, not product pages. A hook keeps them in sync whenever the cart changes.

----

Text:

Every entry in the cart is a [`ListItem`](/reference/classes/list-item) with a `type`. Products use the default type `product`, and shipping costs and discounts use a type of their own. The allowed types are `credit`, `custom`, `discount`, `product`, `promotion` and `shipping`.

Because shipping is just another list item, it needs no content page and no blueprint of its own. It’s part of [`$cart->total()`](/reference/classes/cart/total) like everything else, and [`filterByType()`](/reference/classes/cart/filter-by-type) keeps it out of your product listing.

## Add shipping as a list item

Build the item with [`new ListItem()`](/reference/classes/list-item/__construct) and give it a [`Price`](/reference/classes/price) of its own. A negative price makes it a discount.

```php
use Wagnerwagner\Merx\ListItem;
use Wagnerwagner\Merx\Price;

$cart->add(new ListItem(
  key: 'shipping',
  title: 'Shipping',
  price: new Price(price: 7.99, tax: 0.19, currency: $cart->currency()),
  type: 'shipping',
));
```

> [!CAUTION]
> Always pass the cart’s [`currency()`](/reference/classes/cart/currency) to the `Price`. The cart refuses an item in another currency than its own with [`error.merx.mixedCurrencies.add`](/reference/options/translations/error-merx-mixedcurrencies-add).

## Recalculate whenever the cart changes

Shipping and discounts depend on what is in the cart, so they have to be recalculated after every change. There is no single cart hook — there is one pair of hooks per operation. Point [`cart.add:after`](/reference/options/hooks/cart-add-after), [`cart.remove:after`](/reference/options/hooks/cart-remove-after) and [`cart.updateItem:after`](/reference/options/hooks/cart-update-item-after) at the same function; the [hooks reference](/reference/options/hooks) has the full list.

The function removes both items first and then adds back whatever currently applies. That keeps it idempotent, so it does not matter how often it runs. The static guard matters: the function changes the cart, which fires the very hooks that call it again.

```php title="/site/config/config.php"
<?php

use Wagnerwagner\Merx\Cart;
use Wagnerwagner\Merx\ListItem;
use Wagnerwagner\Merx\Price;

function updateCartExtras(Cart $cart): void
{
  static $isUpdating = false;

  // Adding and removing items fires these hooks again.
  if ($isUpdating === true) {
    return;
  }

  $isUpdating = true;

  $cart->remove('shipping');
  $cart->remove('discount');

  if ($cart->quantity('product') > 0) {
    // Free shipping from 50 onwards.
    if ($cart->total()->toFloat() < 50) {
      $cart->add(new ListItem(
        key: 'shipping',
        title: 'Shipping',
        price: new Price(price: 7.99, tax: 0.19, currency: $cart->currency()),
        type: 'shipping',
      ));
    }

    // 10 off when five or more products are in the cart.
    if ($cart->quantity('product') >= 5) {
      $cart->add(new ListItem(
        key: 'discount',
        title: 'Discount',
        price: new Price(price: -10, tax: 0.19, currency: $cart->currency()),
        type: 'discount',
      ));
    }
  }

  $isUpdating = false;
}

return [
  'hooks' => [
    'wagnerwagner.merx.cart.add:after' => fn (Cart $cart) => updateCartExtras($cart),
    'wagnerwagner.merx.cart.remove:after' => fn (Cart $cart) => updateCartExtras($cart),
    'wagnerwagner.merx.cart.updateItem:after' => fn (Cart $cart) => updateCartExtras($cart),
  ],
];
```

Removing the last product empties the cart completely, because `quantity('product')` is then `0` and neither item is added back.

The discount has a tax rate, like the shipping. Without one it would lower the total and leave the tax as it was. With products at more than one rate, one discount is not enough: add one per rate, as [Coupon codes](/cookbook/coupon-codes) does.

## Keep them out of the product list

[`filterByType()`](/reference/classes/cart/filter-by-type) returns only the items of one type. In the cart snippet from [Displaying order](/guide/getting-started/displaying-order#cart-snippet), loop over the products in the body of the table and give shipping and discounts a row of their own in its footer.

```php title="/site/snippets/cart.php"
<?php foreach ($cart->filterByType('product') as $item): ?>
  <!-- the row of a product -->
<?php endforeach ?>

<?php foreach (['shipping', 'discount'] as $type): ?>
  <?php foreach ($cart->filterByType($type) as $item): ?>
    <tr>
      <th colspan="3"><?= html($item->title()) ?></th>
      <td><?= $item->total() ?></td>
    </tr>
  <?php endforeach ?>
<?php endforeach ?>
```

## Discounts and the total

A discount is a list item with a negative price, and Merx does not stop you from discounting more than the cart is worth. It does refuse to order such a cart: [`isOrderable()`](/reference/classes/cart/is-orderable) is `false` as soon as the total is below zero, and the checkout answers with [`error.merx.cart.notOrderable`](/reference/options/translations/error-merx-cart-notorderable). Check it before you send the customer to the checkout.

A total of exactly zero can be ordered, for example with a coupon that covers the whole cart. Offer a gateway that takes no payment for it, such as `invoice`: Stripe and PayPal cannot charge nothing.

```php
<?php if ($cart->isOrderable() === false): ?>
  <p>This cart cannot be ordered.</p>
<?php endif ?>
```

The [cart API](/reference/api/routes/shop-cart-get) lists shipping and discounts on their own, as `shippings` and `discounts` next to `products`, each with its items and their total.

For how tax is applied to a price, see the [taxes](/guide/configuration/taxes) guide.
